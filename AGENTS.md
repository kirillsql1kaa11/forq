# AGENTS.md

## Стек

SvelteKit 3 + Svelte 5 (руны), TypeScript, Vite 8. SPA через `@sveltejs/adapter-static`. Supabase как бэкенд целиком (Auth, Postgres + RLS, PostgREST, Storage). Серверного кода нет.

## Команды

- `npm run dev` — дев-сервер
- `npm run build` — сборка в `build/`
- `npm run check` — `svelte-kit sync` + `svelte-check`; запускать перед сдачей
- `npm run preview` — предпросмотр сборки
- `npm run icons` — перегенерировать PNG-иконки, фавиконы и знак для шапки из `branding/logo.png` (нужен dev-зависимость `sharp`)
- `npm run og` — перегенерировать `static/og.png` (тоже нужен `sharp`)

## Что важно знать про SvelteKit 3

Эти вещи отличаются от SvelteKit 2 и легко ломают сборку:

- Конфиг только в `vite.config.ts` внутри `sveltekit({...})`. `svelte.config.js` больше не поддерживается и вызывает ошибку `config_file_unsupported`.
- `$lib` удалён. Импорты только `#lib/*`, маппинг в `package.json` → `imports`.
- `$app/stores` удалён. Состояние страницы — `import { page } from '$app/state'`, без `$page`.
- Env: объявление в `src/env.ts` через `defineEnvVars`, чтение из `$app/env/public`. Старые `$env/static/public` и `$env/dynamic/public` не существуют.
- tsconfig наследует `$app/tsconfig` (файл генерируется в `node_modules/$app/tsconfig.json`). Пути для `#lib/*` прописаны вручную в `tsconfig.json`, потому что генератор их не создаёт.
- Типы маршрутов лежат в `.svelte-kit/types`, параметры вида `page.params.username` имеют тип `string | undefined` — нужно приводить.
- `$app/paths` экспортирует `resolve`, но не `base`. Ссылки внутри приложения нельзя писать строкой: `resolve('/settings')`, `resolve('/u/[username]', { username })`. Так базовый путь из `paths.base` подставляется сам, и сборка работает и в корне домена, и в подпапке. Базовый путь задаётся переменной окружения `BASE_PATH` при сборке.

## Структура

- `src/lib/api.ts` — единственное место с запросами к Supabase, включая выход из аккаунта, удаление аккаунта, RPC поиска постов, поиск людей, случайный пост и загрузку одного комментария. Ошибки БД переводятся в русские сообщения через `describe(error, kind)`: один и тот же код значит разное в разных местах (`23514` — длина текста, чужой пост при закреплении или несовпавший ник при удалении), поэтому вид ошибки передаётся явно. Ошибки Auth — через `authMessage()` по тексту ответа.
- `src/lib/posts.svelte.ts` — `PostList` управляет списком постов: курсорная пагинация, оптимистичные правки с откатом, временные записи для оптимистичной публикации (`placeholder` → `settle`/`drop`, временный id отрицательный, флаг `pending`). По умолчанию курсор — `id` поста; если список упорядочен не по постам (вкладка «Лайки»), лоадер проставляет поле `cursor`, и пагинация идёт по нему. Компоненты `PostCard` управляемые: локальных копий состояния поста нет, иначе после перезагрузки списка данные устаревают.
- `src/lib/draft.svelte.ts` — недописанный пост в `localStorage`, один на браузер. Композер включает это флагом `persist`.
- `src/lib/session.svelte.ts` — пользователь, профиль и счётчик непрочитанных. Внутри `onAuthStateChange` нельзя сразу звать Supabase (дедлок), поэтому загрузка профиля отложена через `setTimeout`.
- `src/lib/format.ts` — время, склонения, а также `tokenize()` (разбор `@упоминаний`, `#хештегов`, ссылок, жирного, курсива, кода и `||спойлеров||`) и `mentionQuery()` (поиск незакрытого упоминания под курсором). Ссылками становятся только домены из `src/lib/links.ts`; `plainText()` заменяет спойлер на `[спойлер]` для уведомлений.
- `src/lib/appearance.ts` — тема и акцент: значения в `localStorage`, применение через `data-theme` и `data-accent` на `<html>`. Тот же разбор продублирован инлайн-скриптом в `app.html`, чтобы не было вспышки светлой темы.
- `src/lib/markup.ts` — чистая функция обёртки выделения маркерами; её используют композер и форма правки поста.
- `src/lib/components/RichText.svelte` — рендер текста с ссылками и раскрывающимися спойлерами. Без `{@html}`, текст остаётся экранированным; состояние раскрытых спойлеров сбрасывается при смене `body`.
- `src/lib/components/PeopleList.svelte` — общий список для `/u/[username]/followers` и `/u/[username]/following`.
- `src/lib/components/PostFeed.svelte` — список постов, действия, необязательный композер. Используется лентой и страницей тега.
- `src/routes/+layout.svelte` — гейт по сессии, редиректы, ссылка на поиск, футер со ссылкой на `/about`, регистрация service worker только в проде.
- `src/routes/search/+page.svelte` — вкладки «Посты» и «Люди»; поиск людей идёт двумя `ilike`-запросами, затем подтягиваются подписки и считается флаг `following`; подписка переключается оптимистично.
- `src/routes/p/[id]/+page.svelte` — комментарии и ответы; ссылка на комментарий имеет вид `/p/id#c<номер>`, при открытии догружает отсутствующий комментарий и родителя, подсвечивает и прокручивает к нему.
- `src/routes/about/+page.svelte` — манифест, пресс-тексты и скачиваемые ассеты; ссылка на страницу в футере.
- `src/routes/+page.svelte` — лента и кнопка случайного поста.
- `scripts/site-url.mjs` — после `vite build` заменяет `http://localhost:5173` в `build/index.html` на `SITE_URL` или Netlify `URL`; `scripts/og.mjs` рисует `static/og.png`.
- `static/sw.js` — service worker: сеть вперёд, кеш как запас, лимит 150 записей. Хеши сборки не знает намеренно, поэтому лежит в `static/`, а не в `src/service-worker`.

## База

Схема в `supabase/migrations/0001_init.sql`, `0002_features.sql`, `0003_counters_and_pins.sql`, `0004_follows_search_account.sql` и `0005_follow_lists.sql`. Все скрипты идемпотентны. Новая порция изменений — отдельный файл `000N_*.sql`, а не правка существующих.

Правила, которые нельзя нарушать:

- Права выдаются точечно: `revoke all`, затем `grant` на конкретные колонки. Добавляя колонку с правом на запись, не забыть `grant update (колонка)`, иначе PostgREST вернёт `42501`.
- Таблицы `likes` и `comments` не имеют политики `DELETE` там, где нужно мягкое удаление. У `posts` политики `DELETE` нет вовсе.
- Представления обязаны иметь `security_invoker = true`, иначе обходят RLS.
- Триггеры, которым нужен доступ за пределами прав вызывающего (`notifications`, `post_tags`, чтение чужих профилей), объявляются `security definer` и `set search_path = public, pg_temp`.
- `notifications` не имеет права `insert` ни у одной роли: строки создают только триггеры. `authenticated` может лишь читать свои строки и менять `read_at`.
- Закрепление проверяется в базе (`enforce_pinned_owner`): чужой или удалённый пост закрепить нельзя. Удаление поста снимает закрепление (`clear_pinned_post`), поэтому `profiles.pinned_post_id` может оказаться пустым в любой момент — интерфейс обязан это пережить.
- Лимиты частоты считают строки под `pg_advisory_xact_lock`. Без блокировки параллельные вставки проскакивают мимо проверки.
- Глубина ответов — инвариант базы (`enforce_comment_depth`), а не интерфейса. Не переносить эту логику на клиент.
- Счётчики лайков и ответов лежат в `posts.like_count` и `posts.comment_count`, их ведут триггеры `sync_like_count` и `sync_comment_count`. Права на запись этих колонок нет ни у кого, «починить» их можно только повторным прогоном `0003_counters_and_pins.sql`.
- Подписки лежат в `follows`, читать их может кто угодно, писать — только со своим `follower_id`. Лента подписок — представление `following_feed` с `security_invoker`; права на него есть только у `authenticated`, для гостя это `42501`, а не пустой список.
- `posts.search` — генерируемая колонка `tsvector` (`to_tsvector('russian', body)`), её нельзя писать руками и не нужно пересчитывать. Поиск идёт только через RPC `search_posts(text, bigint)`: фильтр PostgREST `wfts` собирает запрос в строку и ломает пробелы и кавычки. Функция объявлена без `security definer`, поэтому RLS работает как обычно.
- Удаление аккаунта — единственное место, где приложение трогает `auth.users` и `storage.objects`. Делается в `security definer` функции `delete_account`, ник сверяется с `profiles.username`. Всё остальное уходит каскадом из-за `on delete cascade`.

Без комментариев, включая SQL и docstring. Пояснения — в ответе, не в коде.

## Хостинг

Netlify, статика из `build/`. Конфиг в `netlify.toml`: команда сборки, версия Node, переменные Supabase и SPA-роутинг. Публичные ключи Supabase продублированы прямо там — при их ротации править и `.env`, и `netlify.toml`. Ветка деплоя `main`.

`npm run build` — это `vite build` плюс `scripts/site-url.mjs`: скрипт подставляет в `build/index.html` адрес из `SITE_URL` или системной `URL` Netlify для абсолютных OG-тегов. OG-разметка статична, поэтому карточка одна на все маршруты; не добавлять туда адрес текущей страницы без серверного рендеринга.

Проверено, что `*.pages.dev` и `*.vercel.app` из России недоступны, а `*.netlify.app` и `*.github.io` работают. Менять площадку без повторного замера не стоит.
